# IronLog — тестовый стенд

Публичный стенд для проверки сборок IronLog на отдельном origin, не затрагивая
production и облако.

- Тестовый сайт: https://ironlog-test.github.io/
- Источник кода: https://github.com/tmksdm/IronLog (публичный).
- Ветка источника для публикации: `test-deploy`.

## Назначение

Стенд собирает и публикует **тестовую** сборку IronLog (`npm run build:test`,
режим Vite `testdeploy`) и позволяет проверить её в браузере телефона владельца
до того, как изменения попадут в основную линию.

## Что здесь принципиально отсутствует

- **Учётные данные.** Приложение работает без облака, а тестовая сборка вдобавок
  несёт CSP с `connect-src 'self'`: соединение с любым другим origin запрещено
  самим артефактом.
- **Пользовательские данные.** Стенд не пишет и не читает данные владельца;
  данные живут только в браузере телефона.
- **Секреты.** В workflow стенда нет ни секретов, ни токенов: дерево источника
  забирается анонимно по HTTPS, из прав используется только автоматический
  `GITHUB_TOKEN` с минимальным набором.
- **Исходный код.** Репозиторий не хранит код приложения: workflow забирает
  архив ревизии из публичного репозитория источника.

## Как публикуется сборка

`.github/workflows/publish.yml`, только `workflow_dispatch`:

1. **build** — разрешает HEAD ветки `test-deploy` источника, забирает архив этой
   ревизии анонимно, ставит зависимости, прогоняет `lint` и тесты, собирает
   `npm run build:test`, проверяет артефакт (`scripts/ci/check-artifacts.mjs
   --mode test --self-test`) и публикует его как артефакт Pages.
2. **deploy** — задание в защищённом окружении `github-pages`: прогон
   останавливается и ждёт одобрения владельца, только после этого файлы попадают
   на сайт.
3. **verify** — сравнивает то, что реально отдаёт сайт, с собранным артефактом:
   `buildId` из `version.json`, sha256 `index.html` и наличие тестовой CSP.

Проверенная сборка опознаётся парой `buildId` + sha256. `buildId` встроен в
`sw.js`, поэтому повторная публикация той же версии доезжает до уже
установленного приложения: имя кэша service worker меняется вместе с id.

## Правила безопасности

- Публикация выполняется **только вручную** (`workflow_dispatch`), **никогда** по
  push, по расписанию или по цепочке других workflow.
- Развёртывание проходит через защищённое окружение `github-pages` с обязательным
  одобрением ревьювера: без подтверждения человеком сайт не публикуется.
- Публикуется только HEAD ветки `test-deploy` источника; произвольный SHA и
  откат по журналу пока не поддерживаются (см. ниже).
- Права выдаются по заданиям: `pages: write` и `id-token: write` — только
  развёртыванию; на верхнем уровне только `contents: read`.
- Production-сайт https://tmksdm.github.io/IronLog/ этим репозиторием не
  затрагивается; данные пользователя не изменяются.

## Журнал публикаций (не реализован)

Опубликованные сборки должны регистрироваться в ветке `journal`, файл
`published.json`: версия схемы и массив записей, по одной на публикацию. Запись
опознаёт опубликованные байты парой `buildId` + `digest`.

**Требование — логическая append-only семантика.** Правила защиты ветки
запрещают удаление и non-fast-forward, но они защищают историю коммитов, а не
содержимое файла, поэтому содержимое проверяется отдельно. Контракт обязателен
для задания журнала:

1. Перед записью задание читает текущий `published.json` из ветки `journal` и
   разбирает его.
2. Новое содержимое строится только как прежние записи без изменений плюс новые
   в конец.
3. Массив прежних записей обязан быть точным префиксом нового массива: ни одна
   запись не изменена, не удалена и не переставлена, версия схемы не менялась.
4. При любом расхождении задание падает закрыто: запись не выполняется, и
   публикация не считается зарегистрированной.
5. После записи файл перечитывается из origin, и проверка префикса повторяется.

Реализация этой проверки не выполнена: задания журнала в workflow нет,
`published.json` остаётся пустым реестром.

## Ограничения

- Адрес `ironlog-test.github.io` задан именем организации и не меняется.
- Сайт публичный: тестовые сборки видны всем.
